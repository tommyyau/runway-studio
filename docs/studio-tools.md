# Runway Studio tools

`runway-studio` is a read-only companion for Claude and Codex cards. It reads Studio’s private normalized state and existing local history; it never reads credentials, requests provider APIs, refreshes Runway, or changes tracker settings. Studio must be running for actionable data. Keep the other tracker GUIs closed. Without a valid Studio heartbeat, the shipped tool reports unavailable; it never probes another app’s HTTP server.

- `runway-studio statusline` prints a compact summary. Add `--json` for machine-readable cards, meters, source and observation timestamps, and locally recorded daily usage where available. Local history is machine-local across accounts; do not sum account cards. Cost figures estimate API value, not subscription bills. Offline results are cached and explicitly stale; missing values are not zero.
- `runway-studio wait codex --metric Session --timeout 300 --poll 15` exits 0 when a fresh, positive allowance is observed, 1 on timeout, and 2 for invalid arguments. `--timeout` is positive and at most 86400 seconds; `--poll` is 1–3600 seconds. The default metric is `Session`, timeout is 300 seconds and poll interval is 15 seconds. A reset time in the past is not proof of replenishment: the tool waits for a fresh reading. No provider request is made by the wait command.
- `runway-studio mcp` serves newline-delimited JSON-RPC over stdio. Configure an MCP client with this command and argument. The read-only `status`, `limits`, and `local_usage` tools accept an optional `provider` string. They return source timestamps and freshness alongside data. No diagnostic output is written to stdout.

Use an exact card ID such as `codex@...` when multiple accounts exist. A family selector is accepted only if it resolves to exactly one card; the tools do not merge accounts. Cached data shown while Runway is offline may belong to a previous account. Each meter reports its source and freshness; a card is a tracker card and its account identity is not independently verified. Daily costs include a `costsIncomplete` flag for unknown prices or missing costs alongside positive token counts. Wait uses the current card’s fresh normalized consumption resource, including model-specific labels exposed by Studio. A missing local history means unavailable, not zero usage.

For a local build, run `swift build -c release --product runway-studio`, then place or symlink `.build/release/runway-studio` into a directory on your PATH. If the app distribution includes the executable, use the shipped executable as the symlink target instead so it survives build cleanup.

Studio-only mode uses `~/Library/Application Support/RunwayStudio/latest-state.json`. A heartbeat over 90 seconds old is unavailable; an existing invalid file never falls back to another source. Status output includes per-family `nextAttempts`. The wait command and MCP readers do not initiate provider checks, and all consumption resources exposed by Studio, including model-specific ones, remain available.

Local daily history is read from Studio’s own `provider-cache.json`. It has no runtime dependency on the original Runway preferences or helper.
